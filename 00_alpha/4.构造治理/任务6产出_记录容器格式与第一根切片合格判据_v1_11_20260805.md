## 0. 三容器路由规则（防误归档）

切片施工过程中撞到问题时，按下表分流登记，避免三容器混用：

| 遇到的情形 | 归档去向 |
|---|---|
| 需用某个**尚不存在**的命名/接口/模块（缺物） | 模板一（候选清单格式） |
| 某对象/触点**存在**，但其定义/判定**悬于哲学分歧、当场无法裁**（悬物） | 模板二（哲学未决登记格式） |
| 上游产物**已存在但有错**（出处/行号/判定错） | §6.3缺陷回传（line 131-133），非本产出容器 |
| 运行期harness**偷接数据源**（input非人造/接IBKR/QuantConnect/历史/实时/文件） | 模板三D段前置合规断言检出→判**不合格**→§6.3登记（裁决1"不接数据源，全程强制"） |

四情形按上表分流互斥（缺物／悬物／错物／运行期偷接）。同一条目若跨类，拆分登记，不合并。

## 1. 模板一：候选清单格式（缺命名/缺接口/缺模块记录容器）

**用途**：垂直切片撞到"要用某个尚不存在的命名/接口/模块"时，登记该缺口，**不就地创造定义**。

**越界纪律（强制）**：本容器只登记"缺什么"与"指向何处补"。**不在容器内定义任何接口签名、命名规范、模块结构**——定义动作是缺口回传后的下游任务，越界填入即构成§6.1"越界偷渡接口/命名/模板"缺陷。

**字段定义（空模板）**：

| 字段 | 定义 | 取值约束 |
|---|---|---|
| 条目ID | 缺口条目唯一标识，供跨切片/回传引用 | 自定义前缀+序号；ID方案不预设固定值 |
| 缺口类型 | 缺命名 / 缺接口 / 缺模块（任务全集§一 line 39定义行三类）。三类不足时可扩，扩类须显式标注"超出定义行三类"并说明理由 | 枚举含显式扩展位 |
| 缺口描述 | 切片需要而当前不存在的对象在**功能上"应能做什么"**——只描述功能需求 | 文本；**禁含接口签名/命名规范/模块实现** |
| 触发切片 | 撞到此缺口的切片元素（对象标识） | 指向已选定切片对象 |
| 触发场景 | 切片执行到何种操作时需要它（§6.3同名字段） | 文本 |
| 出处 | 缺口暴露点在切片/产物中的具体位置（§6.3同名字段） | 文档+节+行/步 |
| 当前占位处理 | 为使切片继续，当前如何规避（如：人造input承担、语义引用携带、桩替代） | 文本 |
| 阻断性 | 是否阻断当前切片跑通 | 二值：阻断 / 可继续（占位） |
| 建议归属 | 缺口应由哪一层/哪一任务补——**仅指针，不含定义内容** | 指向层/任务 |
| 状态 | 条目生命周期 | 开放字段，示值：open / 已回传(§6.3) / 已补 / 递延 |

## 2. 模板二：哲学未决登记格式

**用途**：切片撞到"某对象/触点的定义取决于哲学观、当场无法裁决"时登记。与模板一区别：对象**可能存在**，但其定义/判定悬于哲学分歧。

**越界纪律（强制）**：本容器只登记"未决什么、悬于哪个哲学分歧、闭合条件"。**不在容器内代做哲学裁决**——裁决是KD/下游动作，容器内代裁即越界。

**字段定义（空模板）**：

| 字段 | 定义 | 取值约束 |
|---|---|---|
| 登记ID | 未决条目唯一标识 | ID方案不预设为任何具体值（裁决2：§5实存标记为例证，非模板固定枚举项） |
| 触发对象/触点 | 哲学未决所附的对象、对象对或触点 | 指向对象/对象对 |
| 未决内容 | 具体哪一项定义/判定当场无法确定 | 文本 |
| 分歧哲学观 | 定义取决于哪一哲学承诺/两种读法之别——无法当场裁的症结 | 文本 |
| 触发场景/时点 | 切片执行到何处、何时暴露此未决 | 文本 |
| 出处 | 对象与哲学承诺在基础资料中的位置 | 文档+节+行 |

## 3. 模板三：第一根切片合格判据（D段①②③经KD共定定案、④撤销）

**唯一权威依据**：裁决1（§二 line 47）——"图纸切片末端统一采用：人造input + 一次性harness真跑出数 + 对合格判据断言，不接数据源。全程强制。" 本模板严格三段对应，不引申、不改写。

**适用范围**：单根合格容器。适用于任一被选为第一根的对象**及后续每一根**（裁决1全程强制），**不预选具体对象**。多根并行时每根独立走一遍 A–D。

**核心设计**：被测对象的**实质判据＝该对象自身的Q4判据**（Step2 §2.x产出、Step4 §4.2重述）。本模板只定义"如何跑、如何断言"的容器，**不新造任何对象级判据**。

### A. 人造input段（对应裁决1"人造input"）

- **定义**：手工构造的输入，覆盖被测切片对象Q4判据所需的最小输入结构。
- **强制约束**：**不接任何数据源**——IBKR / QuantConnect / 历史行情 / 实时行情 / 文件数据源一律禁止（裁决1"不接数据源，全程强制"）。
- **形态**：由对象Q4判据的"喂什么"决定。
- **可判性要求**：input须使期望输出可由**独立路径**手算/独立复算得出，否则无法断言。

### B. 一次性harness段（对应裁决1"一次性harness真跑出数"）

- **定义**：一次性夹具，喂入人造input，驱动切片对象端到端计算，捕获输出数。
- **强制约束**：
  - **一次性**——不建常设pipeline / 数据接口 / 持久服务（建常设即空演绎＋越界模块）。
  - **真跑**——须实际执行产出数，非纸面推演（裁决1"真跑出数"）。
- **职责边界**：harness只负责"喂入→驱动→捕获→断言"，不承担数据获取、不承担生产集成。

### C. 跑出的数 / 数的形态（对应任务定义行"末端跑出什么数、数呈什么形态"）

- **定义**：harness捕获的切片对象实际输出。
- **形态口径**：以被测对象Q4判据"出什么"为准（形态谱系为开放集，非闭枚举；例证见§5，裁决2不预取为结论）。

### D. 合格断言（对应裁决1"对合格判据断言"）

- **断言基准**：被测切片对象自身的Q4判据。本模板不新造对象级判据。
- **断言机制**：
  0. **前置合规断言（合格前置，先于数值比对，v1.2依D-T6-03增）**：断言 (i) 本次input确为人造构造；(ii) harness全程无数据源接入（IBKR/QuantConnect/历史行情/实时行情/文件数据源）；(iii) 独立复算路径自clean人造input独立推导期望值，不得取自harness中间量或任何数据源派生量。任一不满足即判**不合格**，不进入数值比对——将裁决1"不接数据源，全程强制"operationalize为合格判据的实际enforce步，堵VEX-8类"数值自洽但偷接数据源"漏检。
  1. 由人造input经**独立路径**复算期望值（独立于harness实现的计算路径）。
  2. harness实跑输出 vs 独立复算期望值，逐项/逐分量比对。
  3. 附加断言按对象Q4判据要求施加（类型谱系为开放集，例证见§5）。
  4. 全部断言（含step 0前置合规）通过＝合格；任一不符＝不合格，按§6.3登记（承接项目二值缺陷规则）。
