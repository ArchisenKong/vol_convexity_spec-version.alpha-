### 2.10 KD-P2-11 ＋ KD-P3-01 · 断言判定基面（合并，五点）

**代定＝合并统一裁，五点如下。**

**① A2' × D-3 条款冲突（FR-P2-16／盲-1）——认定原条款在 `verify/` 面不可满足，须改写而非以排除口径打补丁。**

条款改写候选：
> A2' 之射程：`entity/` 内标记命中 **==0**（不设任何排除）；`verify/` 内**仅允许**三类——D-3 强制取值字面、检测器自身、记录件与断言日志之描述性提及——**且须逐条声明并给理由**。**黑名单哈希渗透（主判据）不设任何排除，射程为 `entity/`∪`verify/` 全量。**

**理由**：P2' 之排除口径逐条合理，但形态是「条款不可满足 → 逐条打补丁」；补丁数量将随条款集增长，且每次补丁都是一次判断。改写后「不可满足」消失，排除成为条款内在结构。

**② A8' 名/值两读——采值面。**条款文字由「字段字面」改为「字段**值**」，两读消除。理由＝合乙-4 立法目的（凭据**值**不落盘）；P3' 独立复扫已证凭据值面命中 0。

**③ `__pycache__` 排除——采纳。**house 先例 GL-06 F-7 明载，非本位新立。

**④ P3-d（声明与实现不等价）——认定为缺陷，且宜改实现而非改声明。**

事实：声明「剥离注释/docstring」，实现为 tokenize STRING token **全量替换**（含代码行内字符串常量）。
**关键推论**：字符串常量是**数据面**；剥离它使 A4'（forbidden 关键字）与 A7'（破坏性动作）在**字符串端点形态**下失去检出力——例如以字符串形式表达之 API 端点路径将不被检出。本发实测该风险**未兑现**（8 处命中全在 module docstring 内，P3' 零剥离复核证成），但**检出力缺口客观存在**。
**代定**：实现改为「剥离注释与 **docstring**（即模块/类/函数首个 STRING 表达式语句），**保留代码行内字符串常量**」；声明随之与实现等价。

**⑤ P3-e（A3' json-only 射程）——补声明，并追加待成文项。**

补声明：A3' 射程＝`probe/raw` 之 `.json` 件。
**追加待成文项**：`probe/raw` 现有 **12 件 `.txt`** 无 JSON 载体、无 D-3 标记位。「**非 JSON 原件之 D-3 承载形态**」须成文（候选：同名 `.meta.json` 伴生件／目录级声明／文件名前缀）。**本代定不选形态**，登记为待成文。

### 2.11 KD-P3-02 ＋ KD-P3-06 · 义务面与检测面无对表机制（合并）

>
> **（乙）检测射程对表**：凡设机械检测者，其**判定射程**须与**义务面全集**逐条对表，对表结果入断言日志；射程窄于义务面者须**显式声明并给理由**。
