# QC 环境探测 · 任务书 v1.0 · 20260814

## 0. 本任务的性质（先读，决定全部行为）

**这是环境探测，不是回测，不是策略开发，不是让代码跑通。**

目标是查清 QuantConnect free 档账户下，哪些通道通、哪些不通、在哪一步以什么形式被拒。

**被拒是有效产出。** 每一个 403、每一条报错、每一处配额上限，都是本任务要采集的材料。不要为了让流程走下去而绕开阻断点。

三态判定：
- **F0 通过**：该步按预期完成
- **F1 摩擦**：完成了但有代价（降级、配额、额外步骤、警告）
- **F2 阻断**：无法完成

F1 与 F2 同样是有效产出，不是失败。

---

## 1. 执行纪律（硬约束）

1. **缺参数即停**。任何本任务书未显式给出的值（账户凭据、路径、日期、标的），停下来问，不要猜、不要填默认值、不要用占位值继续。
2. **不购买任何数据**。禁止 `lean data download`、禁止设 `--data-purchase-limit`、禁止任何触发计费的操作。
3. **不寻找替代数据源**。禁止 yfinance、爬虫、第三方 API。缺数据即停并报告。
4. **不写有收益指标的算法**。本任务的算法只用于探测通道，不得包含任何策略逻辑、不得输出夏普/收益类指标。
5. **不绕过阻断点**。撞到 403/配额/权限拒绝，记录后停在该步，报告，等指示。不要自行改用其他路径继续。
6. **凭据不经聊天传递**。QC 的 user id 与 API token 由执行人在终端交互式输入，禁止写入任何文件、禁止在对话中转述、禁止截图。若凭据已经以任何形式暴露，作废并重新生成。
7. **全程留痕**。每一条命令的完整命令行、退出码、stdout、stderr 全部落盘，不做摘要式省略。

## 3. 执行步骤

每步执行前先在 `probe/logs/` 建对应日志文件，命令用 `2>&1 | tee` 落盘。每步结束后立即在记录表追加一行，不要攒到最后写。

### E0 · 本机前置

采集并写入 `probe/env/host.json`：

- 操作系统与版本
- Python 版本、路径
- pip 版本
- `docker --version`、`docker info`（Docker 是否已装、daemon 是否在跑）
- 可用磁盘空间（LEAN 镜像数 GB）

**判定**：Docker 不可用 → 记 F2，E6/E7 无法执行，但 E1–E5 仍可继续。

### E1 · 安装 lean CLI

```
pip install --upgrade lean
lean --version
```

记录：安装是否成功、lean 版本号、是否有依赖冲突警告。

### E2 · lean login（free 闸门实测点 ①）

**这一步需要执行人交互输入 QC user id 与 API token。凭据从 quantconnect.com 账户页取，直接在终端输入，不经任何中间载体。**

```
lean login
lean whoami
```

**这是本任务的第一个关键判定点。** 官方文档写 CLI 须付费档成员，但有社区报告 free 档可用。实测结果决定后续全部路径。

记录：是否放行、若拒绝则错误码与原文、`lean whoami` 返回的组织档位信息。

### E3 · lean init

```
mkdir qc-workspace && cd qc-workspace
lean init
```

完成后**完整清点** `data/` 目录，写入 `probe/env/data_inventory.txt`：

```
find data -type f | sort
du -sh data
find data -type d -name "option*"
```

记录：样本数据实际覆盖哪些资产类别、哪些标的、哪些日期区间、是否含期权样本。

### E4 · 建项目并推送（写入类 API 实测）

```
lean create-project "TR2-ENV-PROBE"
lean cloud push --project "TR2-ENV-PROBE"
```

用 `create-project` 生成的默认 `main.py`，**不要修改它**。

记录：push 是否成功、云端是否建出项目、`config.json` 内是否写入 cloud-id、耗时。

### E5 · push→pull→diff 核证

```
mkdir -p ../probe/verify
lean cloud pull --project "TR2-ENV-PROBE" --output ../probe/verify
diff -r "TR2-ENV-PROBE" ../probe/verify/TR2-ENV-PROBE
sha256sum TR2-ENV-PROBE/main.py ../probe/verify/TR2-ENV-PROBE/main.py
```

（`--output` 选项若不存在，改用先复制本地目录再 pull 的方式，并记录该选项缺失这一事实。）

记录：diff 是否为空、两份 SHA256 是否一致、pull 的实际落盘位置与是否覆盖了本地。

**这一步在验证一件事：云端副本能否进入指纹链。** 若 diff 不为空，记录差异的具体内容（换行符？编码？QC 侧自动改写？）。

### E6 · 云端回测触发与结果读取（读取类 API 实测点 ②）

```
lean cloud backtest "TR2-ENV-PROBE" --name "env-probe-01"
```

**这是第二个关键判定点。** 观察并记录：

- 触发是否成功
- 结果是否回传到终端／本地
- 若回传，落在哪个路径、包含哪些文件（统计 JSON？订单？图表？日志？）
- 若不回传，错误码与原文
- 是否有配额提示、排队提示、节点等待

若结果不回传：不要改用其他方式取，记 F2 并停在这里报告。

### E7 · 本地回测（free 闸门实测点 ③）

```
lean backtest "TR2-ENV-PROBE"
```

记录：是否需要拉 Docker 镜像、镜像 tag 与 digest、是否被档位拒绝、若成功则结果落盘路径与内容清单、耗时。

### E8 · 裸容器路径（兜底通道核证）

```
docker pull quantconnect/lean
docker image inspect quantconnect/lean --format '{{.Id}} {{.RepoDigests}}'
docker run --rm --entrypoint bash quantconnect/lean -c "python --version; python -c 'import sys,platform;print(sys.version);print(platform.libc_ver())'"
```

记录：镜像 digest、容器内 Python 版本、libc 版本。

**这一步与账户档位完全无关**，用于确认在 E2/E6/E7 全被拒的情况下是否仍有可用路径。

## 4. 记录表格式

写入 `probe/notes/环境探测记录.md`，每步一行：

| 步骤 | 命令 | 退出码 | 三态 | 现象描述 | 日志文件 |
|---|---|---|---|---|---|

「现象描述」写实际发生了什么，不写推测原因、不写"应该是因为"。原因分析单独成节，与现象分开。

**未撞到摩擦的步骤也要显式记录**，写「F0，无摩擦」，不要因为顺利就跳过不记。

## 5. 产出物

任务结束时，`probe/` 下应有：

1. `logs/` — 每步完整日志
2. `env/host.json` — 本机环境指纹

6. `notes/摩擦清单.md` — 所有 F1/F2 逐条列出，含错误原文
7. `SHA256SUMS` — 上述全部文件的哈希

最后执行：

```
cd probe && find . -type f ! -name SHA256SUMS -exec sha256sum {} \; | sort -k2 > SHA256SUMS
```
