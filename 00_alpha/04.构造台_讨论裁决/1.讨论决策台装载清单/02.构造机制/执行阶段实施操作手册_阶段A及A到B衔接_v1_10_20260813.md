## 0. 为什么阶段B不展开（先说清留白）

本手册到"阶段A→B 衔接点"为止，不展开阶段B内部（执行切片怎么打、回测/模拟/实盘子阶段怎么转）。这不是遗漏，是构造模式支柱①的践行：

阶段B的操作序列若现在写，就是在阶段B的实体（执行切片、真实回测数）出现之前，凭想象预写操作规矩——正是"实现层不能演绎"所禁止的正推。阶段B的展开，须待进入阶段B、有实体后，按同一构造模式反推。

所以"阶段B留白"与后文若干开放项标"实测后定"是同一件事的两面：实体未到，不预写。读者读到阶段B处无操作指引时，应理解为"此处按纪律留白，待实体到位再反推"，不是文档缺章。

```
        G-1读法：以持续迭代可用状态替代终止性完成判据
          │
阶段5  阶段A产出成形
        代码仓 + 若干模块 + 每模块内"思想到可跑代码"的一阶实体 + 经验证的治理纪律
          │
═══════ 阶段A→B 衔接点（本手册到此为止）═══════
          │
阶段6  阶段B：按图施工（本手册不展开，待进入时反推）
        执行切片 → 回测出PnL → 同源同核回测/实盘 → 子阶段转换 → 铺开
```

**一阶与二阶如何分别产出又合成整体**：
- 一阶实体：每根切片产出一个"从思想钻到可跑代码"的具体实例（阶段1、3 持续产出）。
- 二阶规矩：从多根切片的产出归纳出骨架——一阶实体（正例，供模块/命名/共享函数）＋撞墙清单（缺口信号，供新建规矩与横切纪律）（阶段2 首次、阶段3 持续修订）。
- 合成：不是把一阶实体事后拼接，而是让所有一阶实体共同插入同一副由切片产出归纳出的骨架（阶段3 生长机制）。整体 = 一阶实体集 × 承载它们的骨架。一阶实体在此有双重身份：既是归纳骨架的输入（正例样本），又是被骨架组织的对象。

## 2. 单根切片操作序列（模板三 A→B→D）

打一根切片是多步、有数据依赖的过程，不是一步生成。A→B→D 的先后由数据依赖决定（非任务6显式登记的施工步骤序），C 为 B 的产物形态说明、非独立动作。

**A · 人造 input 设计**
手工构造覆盖该对象 Q4 判据所需的最小输入。不接任何数据源（裁决1强制）。产出：一份 input 数据/结构。
前置动作：取该对象 Q4 判据原文，含继承链校验（如 Q4 判据继承自上游行，须溯源完整，不可拿不完整判据设计 input）。

**B · 一次性 harness 真跑**
写一次性 harness，喂入 A 的 input，实际执行代码跑出数。必须真跑，不纸面推演。不建常设 pipeline（裁决1"一次性"）。产出：实际输出。

**C · 跑出的数（B 的产物形态）**
不是独立步骤，是 B 输出的形态说明——用来对齐该对象 Q4 判据要求的输出形态（标量/向量/多分量等）。

**D · 合格断言**
依赖 A 和 C。三步顺序：
1. step0 前置合规断言：input 确为人造、harness 未接数据源。不过则该根直接判不合格，走缺陷回传。
2. 数值比对：另写一条**独立实现**（不复用 B 的代码/思路）复算 A 的 input 应得结果，与 C 逐项比对。实现路径独立是硬要求。容差口径依任务6产出（v1.7，D段①）：(a) 离散/精确有理计算＝0（bit-exact，裁决13）；(b) 连续解析计算＝相对 diff ≤ 1e-12（裁决13设立子口径、裁决19修订锚定值）。〔并入源：W-3〕
3. 附加断言：形态齐备、判据覆盖等。
全部通过 = 该根合格；任一不符 = 按缺陷回传登记。

**撞到缺口时的三容器路由**（A/B/D 任一环节都可能撞到，撞哪段在哪段插入登记，不等全跑完再补）：
- 缺物（需要但不存在的命名/接口/模块）→ 模板一登记
- 悬物（对象存在但定义悬于哲学分歧、当场无法裁）→ 模板二登记
- 上游产物本身有错 → §6.3 缺陷回传
- 跑数时发现偷接数据源 → D 段 step0 直接判不合格 → 缺陷回传
四类互斥、不合并、不预判某根一定撞哪类。可能全程不撞（干净跑通），也可能撞多条。

**一根切片的完整产出**（v1.2 订正结构，B1/B2）：
1. **一阶实体（运行态）**：A 的人造 input（schema＋数据）＋ B 的 harness（算法＋输出真数）。此为归纳消费物。
2. **核验夹具**：D 的独立复算脚本＋断言脚本＋断言日志。仅供 KD 外审复核路径独立与断言咬合力，**不属归纳消费物**（与 §4 输入集边界同口径）。旧表述曾把 D 复算并入"一阶实体"——订正：D 是对实体的检验，不是实体本身。
3. **本根撞墙清单**：模板一/二登记条目（可能为空）。
4. **切片记录**（`切片记录_对象ID_vX_日期.md`，供 KD 入档、归纳直接消费）固定字段：
   - **对象语义（必填）**：一句话陈述该对象是什么、与其输入/输出的关系。依据＝一阶实体定义含"语义如何"（L1）；跨根命名统一靠语义锚（不同根对同一概念可能用不同字段名，仅字段名对齐无法识别同族），故语义必须随每根显式产出，不得只存在于代码注释或会话对话中。
   - **合格判定（必带）**：通过/不通过。§4"只进已通过根"的过滤依据即此字段（运行态包内不含判定）。
   - **本根裁定登记（必填，可为空）**：汇总散落在实体文档中的全部裁定语句（"本根裁定/占位/范围限定/不外推"类）＋指针回原文。逻辑与 B1 同源：语义不得只活在代码注释，裁定不得只活在 schema 文档深处。KD 复核收敛为"读一份切片记录＋按指针抽查"。〔并入源：W-1手册半，裁决21(d)；KD裁定D5（20260711）提前适用，T3-03起已落字段〕
   - 一阶实体文件清单、撞墙清单条目、检验通道记录、KD 登记项（如容差实测值）。
   - **交付件SHA256指纹列（v1.5增，W-13(17)，裁决39-D4）**：切片记录固定字段增指纹列——`entity/`与`verify/`每交付文件之SHA256，随切片记录产出。用途＝外审/增量复核可核证所审对象与交付对象同一，堵"审的与交的不同版"形态。
   - **施工侧模型档申报字段（v1.8增，DOC-17(c)兑现，裁决60-D-f容器＋41-11口径）**：切片记录固定字段增——施工会话之**模型档申报**：**不钉版本号，只钉能力档口径声明**（41-11裁定形态）；用途＝校验侧"fresh context且能力档不低于施工侧"义务之对照基准（外审/增量复核开场核对项）。
- **合格字段层级限定语（v1.5增，裁决53〔判据链L2闭环声明〕）**：本记录之"合格判定"仅指**实现层（L1）合格**——人造input实跑＋断言栈通过；不构成规格层（L2，schema语义相对策略意图之适当性）、结构层（L3，装配后路径级形状）之任何主张。L2状态由翻译审计表覆盖面与三分判别承载；L3判据归阶段B（判据链骨架见裁决53落地文档）。
   - **未通过根同样出记录并入档**（挂起＋登记＋返回条件）；其撞墙清单仍为归纳输入，其一阶实体不进骨架（§4 不进规则）。

切片会话粘贴版（任务包）中的交付清单是本条的执行引用，不得自行增删字段；字段变更以本手册为权威源。

**例外切片撞墙条目限缩（v1.10增，裁决88·递延8兑现；成文源＝裁决85-8原文）**：外部环境实测类例外切片（曳光弹族）**不自立撞墙条目**；撞到之缺口走「呈KD事项登记」通道，摩擦材料挂对应W条目明细（29-F同构）。定性＝此类墙为外部环境摩擦，消费方＝KD裁定与建制反推、非归纳会话，入归纳输入面属类别错置。**边界句**：域内墙材料（如定价口径、IV输入身份）回流至既有撞墙清单**既有条目**不受本限缩约束——限缩的是例外切片**自立新条目**。

## 4. 骨架首次归纳（阶段2）

**动作性质（G-4 口径，已裁·最小充分）**：骨架归纳登记为显式独立动作，产出为独立制品（走版本化留痕）。发起权与产出定案权归 KD——切片产物的收尾注记不得单方面发起归纳、或自行界定归纳范围（防越界，此为 G-4 核心）。

**什么进、什么不进（G-3 维度2，已裁）**：
- 进：已通过根的完整切片产出——一阶实体（正例，供模块/命名/共享函数三要素）+ 撞墙清单（缺口信号，供新建规矩与横切纪律），去重后作为归纳素材。**两者并列主输入**：撞墙清单只记缺口（需要但不存在的东西），共享函数/模块/命名须从已跑通的一阶实体提取（如三根各算vega通过、不撞墙、清单无记录，仅凭清单归纳不出共享函数）。
- **输入集物理边界（v1.2 钉死）**：归纳输入集＝每根 {①运行态实体包（人造 input schema ＋ harness 算法与输出真数）＋ ②撞墙清单 ＋ ③切片记录}。**切片记录必须携带该根通过判定**——"只进已通过根"的过滤依据即此判定；运行态包内不含判定，缺切片记录则该根无法进入归纳（不是默认通过，是无法过滤）。核验夹具（独立复算脚本/断言脚本/断言日志）**不属归纳消费物**，仅供 KD 外审复核，不进归纳素材。
- 不进：未通过根的完整产出排除（含其一阶实体与撞墙清单，建立在未验证实体上，进了污染骨架）。

**产出——骨架初版**：从切片产出（一阶实体正例 + 撞墙清单缺口信号）反推出的二阶结构。模块划分、命名约定、共享计算函数、横切纪律，是**初始预期参考，非封闭产出集**。首次归纳以实际反推结果为准，可增、可拆、可重组，不预锚数量（G-4第4条：不预定义归纳方法与产出完整结构）。

**归纳方法本身不预定义**：怎么去重、怎么提炼，留待首次实际归纳时反推。归纳前预定义方法 = 正推二阶 = 空转（构造模式支柱①）。

**低基数启动的预期管理（G-3 边界2）**：若仅少数根通过即启动归纳，骨架异质性低、可能假收敛。骨架初版薄、不应期待代表性——由后续根撞例外修订。这是特性不是缺陷。

## 5. 生长机制（阶段3，第二批起）

生长不是拼接。多根切片不各自独立开发后设计接口对接，而是共同插入同一副骨架。第二批起，从26留域取对象，套 §2 的模板三 A→D，并**强制复用骨架**，分两个拼接：

**结构拼接（一阶）**：新对象按"它是什么"归入已有模块，复用已有共享函数（如 vega 只调一份，不重写）。同类计算不重复实现。

**治理拼接（二阶）**：新对象的切片产出（一阶实体 + 撞墙清单）去重后并入全局纪律——横切纪律与新建规矩来自撞墙清单，共享函数/模块归属来自一阶实体，与结构拼接同源（结构拼接读实体归模块，治理拼接同样须读实体，非仅撞墙清单）。这份合并结果，就是原先靠空演绎写出的治理文档（B-2）应有的样子——由实体反推得来，取代想象版本。

**骨架修订（撞例外时）**：新对象撞出骨架未覆盖的规矩时，按 G-6（待闭合）处理——修订触发门槛 + 版本化留痕。因 G-1 读法（骨架恒可修订），不存在"冻结后不可改"的僵局；剩余问题仅是"何种冲突够格触发修订 vs 该对象走独立回传"，依首批后实际冲突形态实测登记。

**取对象的两档节奏**：
- 强制回补档（约5项：T3-17ᵃ/T3-18ᵃ、T-78/GK-31可算部分、A2轴一阶候选、T-33等）：第二批启动即触发，前置＝REG-1补齐 + T3-17/T3-18单点改判 + T-78检验通道定义。这三项前置须 KD 单独裁决，不自动满足。
- 闭环倒逼档（其余）：不设批次排程（预排全覆盖 = 横向预规划，违反纵向推进）。由下游消费缺口暴露时被动倒逼入批。可能拖到阶段A后期甚至阶段B才处理，设计允许。

## 6. 批次循环与收敛（阶段3→4）

**循环几次，不以耗尽候选池为条件**。第二批、第三批……循环多次，但冻结/收敛看的是骨架"还会不会变"，不是"打了多少个"。

**收敛判据（G-1 读法，已裁·N待实测）**：以"持续迭代的可用状态"替代"终止性完成判据"。阶段A不设终态冻结点，骨架为持续可修订的活体。防悬置软触发：连续 N 批无新增骨架条目即视为阶段性可用；N 不预设，首批后实测登记。

**收敛锚定稳定性，非数量**：异质性覆盖广的3根可能比同质的10根更快让骨架收敛。新对象套入不再逼出新模块/命名/共享函数、且已有骨架未被推翻，即达实质稳定门槛。

**批次选定Step3工序扩步（v1.5增，DOC-14手册侧，裁决51 §3三钉子）**：自下一批（第四批）选定会话起，Step3（哲学准入）执行面扩为——①逐对象套用《哲学准入×思想宪法对照表》C-1~C-7；②准入级承诺清单扫描（对照表§3三条）；③随行义务登记（§5仪表身份标注等随包义务写入选定产出）；④**术语册对照（55-4c，v1.6加列，第四批起生效不溯及）**：规范层汇编术语册"禁止误用"栏纳入逐对象对照面，命中即登记呈KD。**联动再版条款**：思想层宪法再版→对照表**先行再版**→方可开下一批Step3；对照表滞后即流程异常，停下呈报KD。

## 8. 阶段A→B 衔接点

本节说明衔接处的**原则性咬合**，不展开阶段B内部操作（原因见 §0）。

**衔接点是什么**：阶段A产出的某个工程对象，进入阶段B成为"执行切片"的起点——取该对象，一小段极端行情数据，最糙代码端到端跑通回测，出一个 PnL 数。这是阶段B的第一根切片（同构阶段A第一根切片的角色）。

**两阶段的咬合纪律**（须在衔接处守住，属阶段A遗产、非阶段B新规）：
- **回测/实盘同源同核**：同一个计算核，历史数据喂核 = 回测，实时数据喂核 = 实盘。生死线，不可有两套核。
- **Greeks 自建**：QC/IBKR 只做数据源 + 发单通道，判据不依赖任一家的 Greeks。阈值型判据对 5% 的 Greeks 差异敏感，触发点会翻转——这与阶段A骨架"Greeks 只用同一份定价"是同一条纪律的两阶段延续，在此咬合。

**到此为止**：执行切片具体怎么打、回测→模拟→小额实盘→放量各子阶段怎么转、子阶段转换判据（G-5），均属阶段B内部，待进入阶段B、有实体后按同一构造模式反推展开。现在预写即违反支柱①。G-5 标"阶段B准入前强制闭合"（区别于 G-1 的持续开放，因涉真金白银、容错低）。

## 10. 开放项闭合清点机制（裁决15承接）

〔并入源：W-2，裁决15全文承接，与缺陷回传（任务6产出§6.3）同级〕

**起因**：开放项散在 5 个容器（模板一/二逐根、治理缺口登记、待修登记、缺陷回传条目、S4-b 等封存版内嵌项），闭合条件命中时无强制扫描动作，命中＝靠人记得。KD 判定（20260710）：登记事项的后续处理闭环是**机制动作，非点问题**，机制须贯穿全流程。

**裁定**：
1. **原理**：闭合条件只能被事件命中，清点挂在事件入账点上，不设日历点、不建独立台账制品。**〔55-4a，v1.6成文；机制已自裁决55即时生效，本次成文为追赶〕**清点点②③固定对照基准扩容两容器：**升格候选登记册**（REG-UP强制时点字段）＋**自由度治理册**（信号重呈条件）；逐字对照纪律同既有。
2. **清点点（v1.6起四处）**：
   - ① 校验会话收尾（每根切片外审结束时，固定末位动作）——覆盖实跑产出的新事实（实测值、使用体验、暴露缺口）；
   - ② 裁决落地时（每次 KD 裁决后）——覆盖裁决连锁命中；
   - ③ 归纳会话开头（批次节点）——覆盖骨架产出类条件。**〔55-3c，v1.6〕**清点点③报告写回增登记**治理止损两比值**：本批治理会话数/一阶实体收口数；本批新增裁决位数——**连续两批不降→强制触发治理裁剪裁决**。首个登记点＝第三批归纳会话开头。零新容器。
   - ④ 阶段A→B衔接会话开头（55-4b新设，v1.6）——覆盖§9统一索引所列六容器前置项（裁决15机制内扩展，补点不另开裁决）。
3. **〔KD 补充裁定，随裁决入档〕清点点集合显式标注为不完整**：当前三点覆盖至骨架归纳；须在归纳环节**之后**才能闭合的开放项（如 G-5/G-7 阶段B准入前闭合项、骨架冻结后事件触发项），其清点点尚未设置。后续阶段推进时补充清点点属本机制的机制内扩展（补点不另开新裁决，落手册本节版本化留痕），**机制本身贯穿全流程的定性现在锁定**。
4. **执行**：清点由该会话 Claude 执行（清点＝扫描非裁决，不触"生产者不自审"）；输出＝命中报告（容器×开放条目×闭合条件×是否命中×去向）；命中项提交 KD 二选一——裁闭（留痕入原登记状态字段）或续挂＋理由。**命中判定须逐字对照登记的"触发时点/闭合条件"字段原文，不得以"证据类型出现"代替"触发条件满足"**（首次执行误判 S4-b 的教训入文）。
5. **报告不留存为独立制品**：命中结果写回原登记条目状态字段，不新增第六容器。
6. **失效条件**：清点项超一屏＝膨胀警报（同任务6产出 §6.5）；清点报告积累成追踪系统＝空转复发，回退到只写回状态字段。

**登记措辞纪律**：登记开放项时，触发时点/闭合条件的措辞须显式标注所锚定的产物状态（candidate／落档），防产物两态分离后的触发歧义（实证＝IND-01，归纳会话撞墙记录20260715；D7-6收入）。

## 附：三问自检（"说清楚"的操作定义）

本手册以"读者在任一时点能回答三问"为说清楚的标准：
1. 此刻该做什么动作？
2. 这个动作产出什么？
3. 做完怎么判断能进下一步？

任一时点三问有一处答不上，即该处未说清、需补。阶段B部分三问暂无法回答，是有意留白（实体未到），不计入"未说清"——留白与"未说清"的区别，正是 §0 点破的那层。
