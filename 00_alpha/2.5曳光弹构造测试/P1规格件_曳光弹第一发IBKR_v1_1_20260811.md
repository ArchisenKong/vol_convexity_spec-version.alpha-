## §2 数据隔离规格（85-3 权威条款照录＋特化）

**条款照录（条款消费形态③，diff==0断言见§7）**：

**85-3｜数据接触＝乙案·只读能力探查（A10）＋隔离条款全采（A4 联动）**：

- **乙案边界口径**＝「数值可过线、不可入面」：真实数值只可存在于 probe/ 子树、带 `_probe_` 标记、哈希入黑名单，永不出现在 entity/verify 面。纯「元数据零数值」在 socket API 下不可严格成立，边界改由目录/键名/哈希三重机械检测承载。
- **裁决1 例外条款明文**：射程限定「曳光弹例外切片之 probe/ 子树」，不外溢至任何标准切片。
- **A4 联动落定**：D-1（目录物理三分）＋D-2（数据指纹黑名单，`probe/data_manifest.json` 随 W-25 明细入台账）＋D-3（键名污染标记，`_data_source=external_probe_NOT_FOR_ENTITY`）**全采**，为乙案成立前提；§2 隔离条款落不下则**退甲案不降级执行**。D-4（归纳装载面过滤）按 B 档机械维持（85-10 B1）。

**本发特化（操作面）**：

- 目录物理三分（D-1）：`p2_workdir/ ├─ entity/ ├─ verify/ ├─ probe/`。
  - `entity/`：`engine.py`（v1.3逐字节复用件）＋`probe_harness.py`（纯代码，零真实数值）。
  - `verify/`：断言脚本＋断言日志＋X-1合成输入对比件（合成/确定性数值，非外部数据）。
  - `probe/`：**唯一**可存真实数值之子树。所有外部数据文件名带 `_probe_` 标记。
- D-2：`probe/data_manifest.json` 登记每一外部数据载荷之 SHA256（黑名单），随 W-25 明细入台账。
- D-3：probe/ 内每一外部数据记录（JSON/dict）须含键 `_data_source="external_probe_NOT_FOR_ENTITY"`。
- **乙案边界机械承载**：目录（D-1）／哈希（D-2）／键名（D-3）三重检测；隔离条款任一落不下＝**退甲案不降级执行**（85-3反面条款）。
- **只读纪律（乙案「只读能力探查」派生）**：P2 全程禁止任何下单侧 API（`placeOrder`／`cancelOrder`／改单类）；仅行情、合约、账户/报表**读取**类调用。此条为规格强制项，违反＝F2即停呈KD。
- **paper account 条款（KD裁定20260811，v1.1新增）**：P2 连接目标＝**paper account**，禁连 live。防线定位＝**叠加**于只读纪律之上，非替代——A7禁下单侧API继续全效，paper为万一失守时之第二层。派生记录义务：paper 环境之行情权限/数据面与 live 可能存在差异（延迟行情、部分 tick types 可得性），目标1（IV sourcing）材料须**逐项标注采集环境＝paper**，paper/live 差异本身列为摩擦记录点，不静默等同。
