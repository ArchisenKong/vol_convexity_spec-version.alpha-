## 1. 关于 API 权限 —— 执行人的观察是对的

**执行人提出：free 账户没有 API 权限，如何取得访问？**

该观察与实测吻合。完整经过如下。

### 1.1 API 是什么

`https://www.quantconnect.com/api/v2/`
（`lean/constants.py:85` 的 `API_BASE_URL`）

**这是 QC 官方 API。** 证据：QC 自行发布于 PyPI 的 `lean` CLI 完全建立在其上。
本任务 E1 装的就是这个官方 CLI，其 `lean/components/api/` 下有 19 个 client 类
封装该 API 的 46 个端点。

认证方式（`api_client.py:135-152`）：Basic auth，用户名为 user id，
密码为 `sha256(api_token:timestamp)`，另带 `Timestamp` 请求头。

**执行人自己跑过的每条命令都走它**：`lean login` → `authenticate`；
`lean cloud push` → `projects/*` + `files/*`；
`lean cloud backtest` → `compile/create` + `backtests/create`。
E2 那次 `Hash doesn't match UID` 报错，就是该 API 的认证失败。

### 1.2 free 账户确实曾被 API 权限闸门拒绝

**2026-08-14（信用卡验证前），E6：**

```

Build Request Successful ... Lean Version: 2.5.0.0.18000
Successfully compiled project 'TR2-ENV-PROBE'
Error: Please upgrade to paid account to use the API and other local features.
```

**报错原文里明写 "to use the API"。** 这正是执行人所指的那道闸门，判定 F2。

### 1.3 但闸门不是全域的 —— 同一天有相当多 API 端点是通的

即在 2026-08-14 被上述报错拒绝的同时，以下端点**在同一账户上正常工作**：

| 端点 | 步骤 | 结果 |

## 5. 两个环节的通道实测结果

### 5.1 回测环节 —— 全程可脚本化

触发：`lean cloud backtest`（A 类）→ exit 0，250 秒。
CLI 触发与网页端触发的回测**记录落在同一云端项目、可互相读取**。

可取回的产物：

| statistics（27 键）、runtimeStatistics（8 键）、totalPerformance（3 键） | `backtests/read` | **A** | 734 / 206 / 1824 字节 |
| 订单全量（含成交事件） | `backtests/read/orders` | **B** | 1 单 1455 字节 |
| 完整报告 | `backtests/read/report` | **B** | **433,336 字节**，异步需重试 |
| 净值曲线 | `backtests/chart/read` | **B** | Equity **396 数据点**，异步需重试 |

**回测结果不落盘**：E11 实测回测完成后项目目录零新增文件，
无 `backtests/` 类目录，产物仅在终端输出与云端。

### 5.2 Research 环节 —— 全程可脚本化，但入口在 B 类

```
本地
 ↓  research/read 或 research/create          [B 类]  → sessionId / uri / token / nodeId
 ↓  GET/PUT https://<node>/api/contents/...   [C 类]  文件双向读写，writable: True
 ↓  WSS  https://<node>/api/kernels/<kid>/channels  [C 类]  execute_request，协议 v5.3
 ↓  收 stream / execute_result / display_data
本地
```

实测（E25）：`execute_reply status: ok`，`execution_count: 8`，
stdout 回传，`execute_result` 含 **`text/plain` 59 字节 + `text/html` 785 字节**
（DataFrame 的 HTML 渲染）。

**双向字节保真**：入向 224 字节 `MATCH_INBOUND: True`；
出向去尾标后 `== 原载荷 True`。

**`research/create` 语义分两态**：有会话时幂等返回既有句柄（E26，F0）；
无会话时启动分配并超时（E27，F2，已停测）。

### 5.3 输出回传的完整路径矩阵

| 路径 | 结果 | 类 |
|---|---|---|
| 内核 WebSocket 取 outputs | **✅ 通，含 text/html，双向保真** | C（入口 B） |
| file API 写云端项目 → `lean cloud pull` | **✅ 通，云端逐字节精确；本地行尾转 CRLF** | A |
| `backtests/*` 取回测产物 | **✅ 通，statistics 为 A 类，orders/report/chart 为 B 类** | A + B |
| base64 data URI 浏览器下载 | **✅ 通，224 字节 sha256 逐字节一致** | 浏览器机制 |
| notebook outputs 经 `lean cloud pull` | ❌ 确定性剥离，5 次观测 | — |
| airlock 文件写入 | ❌ 单向不回流 | — |
| ObjectStore | ❌ Institutional 闸门 + job 权限全 false | — |
| IPython FileLink | ❌ 点击显示为空 | — |

**「outputs 恒为空」的机制解释（E24）**：会话内磁盘上的 `research.ipynb` 仅 2 个 cell，
而浏览器前端当时已有 8 个以上 cell 且有输出。**前端执行状态从未写盘**，
输出只存在于前端与内核内存，故 QC 项目存储与 `lean cloud pull` 自然取不到。
**并非 QC 剥离了输出，而是那些输出从未进入项目存储。**

| 本地 ↔ 本地（pull 前后） | 可直接比对，哈希一致 |
| **云端 ↔ 本地** | **必须先归一化行尾（CRLF→LF）**，否则哈希必然不等 |

实证：`main.py` 云端 880 字节 / 本地 901 字节，差 21 = 本地 CRLF 数 21，
归一化后逐字节相同。

`config.json` 每次 pull 被 QC 注入 `python-venv`、`encrypted` 两字段；
`research.ipynb` 每次被 QC 做 JSON 压缩重序列化。**此二者哈希均无法进入指纹链。**
