### 环境事实：本地代理（不作为原因候选）

```
HTTP_PROXY  = http://127.0.0.1:10808
HTTPS_PROXY = http://127.0.0.1:10808
（Git Bash 侧同值；小写 http_proxy / https_proxy 未设）

$ netstat -ano | grep 10808
  TCP    127.0.0.1:10808   0.0.0.0:0        LISTENING     18356
  TCP    127.0.0.1:10808   127.0.0.1:49361  ESTABLISHED   18356
  （另有多条 ESTABLISHED）
```

Python `requests` 默认读取该环境变量，lean 的 API 请求经此代理。
但 HTTPS 经代理为 CONNECT 隧道，无 MITM 时代理无法读取或改写 TLS 内的 `Timestamp` 头；
`REQUESTS_CA_BUNDLE` 未设置，若存在 MITM 则 `requests` 会先行 TLS 校验失败。
实测为服务端正常返回认证错误（`Hash doesn't match UID` 系 QC 侧文案），说明 TLS 通、请求到达 QC。
故代理仅记为环境事实，不作为 F2-02 的原因候选。

### 关键缺口：真实错误码与响应体未获取

`is_authenticated()`（`api_client.py:105-116`）吞掉了服务端的真实响应：

```python
try:
    self.get("authenticate")
    return True
except (RequestFailedError, AuthenticationError):
    self._logger.debug(format_exc().strip())
    return False
```

上抛的仅为通用文案。服务端真实 HTTP 状态码与响应体需 `--verbose` 才能显形
（`_request` 中 `self._logger.debug(f"Request response: {response.text}")`，`api_client.py:153-154`）。
**任务书 E2 要求记录的「错误码与原文」目前仍未取得。**
